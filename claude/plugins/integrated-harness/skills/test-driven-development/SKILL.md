# 測試驅動開發

先寫會失敗的測試、親眼確認它因正確原因失敗，再寫最小實作讓它通過。沒看過測試失敗，就無法證明它能抓到你要防止的錯誤。

## 路由條件

- 新功能、bug 修復、會改變外部可觀察行為的重構時使用；組織規範要求新功能須附對應單元測試。
- 純設定檔、文件、程式碼產生器輸出、一次性探索原型，或專案沒有可執行測試框架時不強制；說明原因及替代驗證方式。
- 不採用「只要有極小可能適用就強制載入」的規則；依行為是否可被自動化測試觀察判斷。
- 既有 Classic ASP／VB.NET／Laravel 維護任務遵循最小變動原則：先補一個描述現有行為的特徵測試，再修改；不為了好測試而重構周邊程式碼。缺乏測試基礎設施時，回報限制並提出最小可行的驗證方式，不自行引入新測試框架。

## 核心鐵律

產品程式碼必須先有一個因「功能缺失」而失敗的測試。

- 若自己在本輪已先寫了未受測試保護的實作草稿，撤回該草稿，從測試重新開始；不要「參考」它再補測試。
- 只撤回自己剛寫的內容；不得刪除、還原或覆寫使用者與協作者的既有修改。
- 確有理由無法先寫測試時（例如外部系統無法模擬），明確說明並取得使用者同意，不自行豁免。

## RED：寫一個會失敗的測試

1. 動筆前先回答：**哪一種產品程式碼錯誤會讓這個測試失敗？** 答不出來，就改測可觀察的行為。
2. 一個測試只驗證一種行為；名稱描述預期行為，名稱出現「和／and」就拆開。
3. 預期值以字面值或手算 fixture 推得，不得呼叫受測程式碼或其 helper 產生預期值。
4. 測試命名、變數與類別使用有意義的英文；說明業務意圖的註解使用台灣繁體中文。
5. 測試資料不得含真實帳號、密碼、API Key、Token 或可識別個人的資料；一律使用去識別化或明顯虛構的值，敏感設定透過環境變數或測試替身注入。

## 確認 RED（不得跳過）

執行該測試並確認：

- 是失敗（assertion fail），不是錯誤（語法錯、找不到模組）。
- 失敗訊息符合預期，原因是功能缺失而非拼字或環境問題。
- 測試一開始就通過，代表在測既有行為；修正測試，不要直接進入 GREEN。

## GREEN：最小實作

- 只寫讓測試通過所需的最少程式碼；不加入測試未要求的選項、擴充點或附帶重構。
- 輸入驗證與跳脫處理（SQL Injection／XSS）屬於該行為的一部分時，先用測試描述再實作。
- 不得 hardcode 任何憑證；需要設定值時從環境變數或 Secret Manager 讀取。

## 確認 GREEN

1. 執行新測試，確認通過且輸出沒有新的錯誤或警告。
2. 測試失敗時修正產品程式碼，不得修改測試去遷就實作，也不得刪除斷言、放寬型別或吞掉例外。
3. 依影響面執行最接近的相關測試；宣告完成前執行專案標準測試入口（例如 `bash tests/run_all.sh`、`dotnet test`、`npm test`、`php artisan test`）。
4. 任何失敗，包括不是你造成的，都要在回報中以名稱列出，不得省略。

## REFACTOR：保持綠燈下整理

只在全部通過後進行：移除重複、改善命名、抽出 helper。不新增行為，且每次整理後重新執行測試。

## 測試品質規則

- **測真實行為，不測 mock**：斷言對象是受測元件的輸出、副作用或狀態，不是 mock 是否存在或被呼叫。
- **在正確層級 mock**：先了解真實相依的副作用，只替換慢速或外部的那一層（網路、資料庫、第三方 API），保留測試依賴的行為為真實實作。
- **mock 資料結構完整**：模擬回應須反映真實資料的完整結構，不只填測試讀到的欄位。
- **只測自己的邊界契約**：不測框架或函式庫本身的機制；常數、getter、單純轉傳不單獨寫測試。
- **不寫變更偵測器**：只會因刻意調整（常數值、訊息措辭、私有結構）而失敗、卻抓不到 bug 的測試不要寫。
- **測試專用程式碼放在測試工具**：只有測試會呼叫的 cleanup 或 helper，不得加入產品類別。
- **Mutation check**：完成前在腦中變異產品程式碼（錯誤常數、錯誤分支、遺漏副作用、回傳空值、漏掉空值／未授權／格式錯誤的驗證），每種實際可能的變異至少要有一個測試會失敗。

## 修 bug 的流程

1. 先寫重現 bug 的失敗測試，確認它在修復前失敗。
2. 根因不明時改用 `systematic-debugging` 定位，再回到本流程。
3. 修復後該測試通過，並作為回歸保護保留。

## 完成前檢查

- [ ] 每個新增或變更的行為都有對應測試。
- [ ] 每個測試都曾親眼看到因預期原因失敗。
- [ ] 實作只包含讓測試通過所需的程式碼。
- [ ] 相關測試與專案標準測試入口均已執行，結果據實回報。
- [ ] 測試資料不含憑證或真實個資，識別字為英文。
- [ ] 邊界條件與錯誤路徑已涵蓋。

本技能不要求建立 Git worktree，也不要求派發子代理。涉及生產環境的變更，測試通過後仍須先在測試環境驗證。
