# 所有平台與發佈版本的一致性契約

日期：2026-07-28

## 決策

任何功能、規則、hook、協定、skill、設定範本或操作流程變更，都必須先建立
「平台 × 模式 × 發佈型態」影響矩陣，再同步修改所有具有相同行為契約的版本。
不適用的版本必須在交付說明中逐項列出原因，不得靜默略過。

根目錄 `AGENTS.md` 是 AI 施作義務的入口；`ARCHITECTURE.md` 記錄各版本的來源、
入口及一致性保障；CI 的逐位元組同步、行為 parity、marketplace、模式切換與
smoke tests 是確定性執行層。

## 理由

本專案同時維護 Claude Code、Codex、GitHub Copilot，以及 copy-in、marketplace、
selector、global install 等發佈型態。只修正眼前副本會造成使用者依安裝方式取得
不同功能或安全行為。單靠文件提醒無法保證一致性，因此規則、架構對照與測試必須
三層並存。

## 實作原則

- 有 `shared/` 單一事實來源或同步腳本時，只修改來源並由工具產生副本。
- 可逐位元組相同的資產以同步測試守護。
- 因平台介面不同而無法共用檔案時，以共同輸入與預期結果驗證行為契約。
- Claude plugin 行為變更須更新 manifest 版號；Codex／Copilot 不另造版號載體。
- 完成交付必須列出已修改、不適用、已驗證及未驗證的版本。
